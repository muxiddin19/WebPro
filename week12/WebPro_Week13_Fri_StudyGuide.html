1. What is Client-Side Routing?

Traditional websites load a new HTML page from the server for every URL change. Single Page Applications (SPAs) load one HTML file and swap components in the browser — making transitions instant, with no full page reload.

React Router intercepts URL changes and renders the matching component without hitting the server.

💡

Key insight: The browser URL bar still changes (so users can bookmark and share links), but only the component tree re-renders — not the whole page.

2. Setup & BrowserRouter

Install the package:

Terminal
npm install react-router-dom

Wrap your entire app in <BrowserRouter> in main.jsx (or index.jsx):

main.jsx
import React from 'react'
import ReactDOM from 'react-dom/client'
import { BrowserRouter } from 'react-router-dom'
import App from './App'

ReactDOM.createRoot(document.getElementById('root')).render(
  <BrowserRouter>
    <App />
  </BrowserRouter>
)
ℹ️

BrowserRouter uses the HTML5 History API. Use HashRouter only if your server can't redirect all 404s to index.html (e.g., GitHub Pages without a redirect rule).

3. Routes & Route

Define all your routes in one place using <Routes> (the route container) and <Route> (one mapping):

App.jsx
import { Routes, Route } from 'react-router-dom'
import Home from './pages/Home'
import About from './pages/About'
import Blog from './pages/Blog'
import Post from './pages/Post'
import NotFound from './pages/NotFound'

function App() {
  return (
    <Routes>
      <Route path="/"        element={<Home />} />
      <Route path="/about"   element={<About />} />
      <Route path="/blog"    element={<Blog />} />
      <Route path="/blog/:id" element={<Post />} />
      <Route path="*"        element={<NotFound />} />
    </Routes>
  )
}

Key rules in v6:

  • path="*" is the catch-all — always put it last
  • :id is a dynamic segment (URL parameter)
  • v6 picks the most specific match automatically — no more exact prop needed

4. Link & NavLink

Never use <a href="..."> for in-app navigation — that causes a full page reload. Use <Link> instead:

Navbar.jsx
import { Link, NavLink } from 'react-router-dom'

function Navbar() {
  return (
    <nav>
      { /* Link: basic navigation */ }
      <Link to="/">Home</Link>

      { /* NavLink: adds 'active' class when route matches */ }
      <NavLink
        to="/about"
        className={({ isActive }) => isActive ? 'nav-link active' : 'nav-link'}
      >
        About
      </NavLink>

      <NavLink to="/blog">Blog</NavLink>
    </nav>
  )
}
⚠️

Using <a href="/about"> inside a React app causes a full page reload and loses all React state. Always use <Link to="/about">.

5. Router Hooks

useParams — Read URL parameters

Post.jsx — route: /blog/:id
import { useParams } from 'react-router-dom'

function Post() {
  const { id } = useParams()  // /blog/42 → id = "42"

  return <h1>Showing post #{id}</h1>
}

useNavigate — Programmatic navigation

LoginForm.jsx
import { useNavigate } from 'react-router-dom'

function LoginForm() {
  const navigate = useNavigate()

  const handleLogin = async () => {
    await login(credentials)
    navigate('/dashboard')          // go forward
    // navigate(-1)                  // go back (like browser back button)
    // navigate('/home', { replace: true })  // replace history entry
  }

  return <button onClick={handleLogin}>Log In</button>
}

useSearchParams — Query strings

Search.jsx — URL: /search?q=react&page=2
import { useSearchParams } from 'react-router-dom'

function Search() {
  const [searchParams, setSearchParams] = useSearchParams()
  const query = searchParams.get('q')    // "react"
  const page  = searchParams.get('page') // "2"

  return <p>Searching for: {query} (page {page})</p>
}

6. Nested Routes & Outlet

Nested routes let a parent component provide a shared layout (navbar, sidebar) while child routes render inside it via <Outlet>.

App.jsx — nested route structure
import { Routes, Route } from 'react-router-dom'
import Layout from './Layout'  // has <Outlet /> inside

<Routes>
  <Route path="/" element={<Layout />}>
    <Route index           element={<Home />} />    { /* "/" */ }
    <Route path="blog"    element={<Blog />} />    { /* "/blog" */ }
    <Route path="about"   element={<About />} />   { /* "/about" */ }
  </Route>
  <Route path="*" element={<NotFound />} />
</Routes>
Layout.jsx — the shared wrapper
import { Outlet } from 'react-router-dom'

function Layout() {
  return (
    <div>
      <Navbar />         { /* shared across all child routes */ }
      <main>
        <Outlet />       { /* child route renders here */ }
      </main>
      <Footer />
    </div>
  )
}
💡

The index prop on a child Route means "render this when the parent path matches exactly." It's the default child route.

Practice Exercises

Exercise 1

What does <Link to="/profile"> do differently from <a href="/profile"> in a React SPA?

Show answer
<Link> uses React Router's history API to update the URL and re-render only the matched component — no full page reload, no network request, React state is preserved.

<a href> causes a full browser navigation: a new HTTP request is sent, the entire page (including index.html) is re-fetched and re-parsed, and all React state is lost.

Exercise 2

You have a route /products/:productId/reviews/:reviewId. Write the useParams call to read both parameters.

Show answer 
import { useParams } from 'react-router-dom'

function ReviewDetail() {
  const { productId, reviewId } = useParams()
  // /products/42/reviews/7 → productId="42", reviewId="7"
  return <h2>Review {reviewId} for Product {productId}</h2>
}
Note: useParams returns strings — convert with Number(productId) if you need a number.

Exercise 3

After a form submission succeeds, you want to redirect the user to /success and prevent them from going back to the form with the browser back button. What navigation call do you make?

Show answer 
const navigate = useNavigate()

// After successful submit:
navigate('/success', { replace: true })
The replace: true option replaces the current history entry instead of pushing a new one, so pressing Back skips the form page entirely.

Exercise 4

What is the purpose of the <Outlet /> component, and where does it go?

Show answer
<Outlet /> is a placeholder inside a parent (layout) component that tells React Router where to render the matched child route's element.

It goes inside the layout component (e.g., between a Navbar and a Footer). When the URL matches a child route, that child's component renders in place of <Outlet />.
