1. What is React & JSX?

⚛

React in one sentence

React lets you describe what your UI should look like for a given state, and it handles updating the DOM efficiently when state changes.

JSX is a syntax extension that lets you write HTML-like markup inside JavaScript. It is compiled to React.createElement() calls by Babel/the bundler.

// JSX (what you write) const element = <h1 className="title">Hello, {name}!</h1>; // What it compiles to (you never write this) const element = React.createElement('h1', { className: 'title' }, 'Hello, ' + name + '!');
💡

JSX differences from HTML: Use className instead of class, htmlFor instead of for, and self-close all void elements: <img />, <input />, <br />.

// JSX rules function App() { const user = 'Amir'; return ( // Must return ONE root element (or use <>...</> Fragment) <div className="app"> <h1>Welcome, {user}!</h1> {/* JS expressions in {} */} <p>Today: {new Date().toDateString()}</p> <img src="photo.jpg" alt="Profile" /> {/* self-closed */} </div> ); }

2. Functional Components

A functional component is a JavaScript function that returns JSX. Component names must start with a capital letter.

// Minimal component — a plain JS function function Greeting() { return <h2>Hello, World!</h2>; } // Arrow function syntax — also valid const Greeting = () => <h2>Hello, World!</h2>; // Use it like an HTML tag (must be uppercase first letter) function App() { return ( <div> <Greeting /> <Greeting /> </div> ); }
⚠️

Capital letter matters: <greeting /> renders as a plain HTML element. <Greeting /> calls your function. Always capitalize component names.

Component returning multiple elements

// Use a Fragment <>...</> to avoid an extra wrapper div function UserCard() { return ( <> <h3>Zulfiya Karimova</h3> <p>Computer Engineering · Year 3</p> </> ); }

3. Props — Passing Data

Props (short for properties) are the mechanism for passing data from a parent component to a child. They are read-only inside the child.

// Parent passes props like HTML attributes function App() { return ( <div> <StudentCard name="Amir Tashkentov" year={2} /> <StudentCard name="Gulnora Nazarova" year={3} /> </div> ); } // Child receives props as an object (first argument) function StudentCard(props) { return ( <div className="card"> <h3>{props.name}</h3> <p>Year {props.year}</p> </div> ); } // Destructured — cleaner style (preferred) function StudentCard({ name, year }) { return ( <div className="card"> <h3>{name}</h3> <p>Year {year}</p> </div> ); }

Default props

// Default values via destructuring default syntax function Button({ label = 'Click me', color = 'blue', disabled = false }) { return ( <button style={{ background: color }} disabled={disabled}> {label} </button> ); } // All three are valid: <Button /> {/* label="Click me", color="blue" */} <Button label="Submit" /> {/* color still "blue" */} <Button label="Delete" color="red" /> {/* custom both */}

props.children

// Anything between opening and closing tags becomes props.children function Panel({ title, children }) { return ( <div className="panel"> <h2>{title}</h2> <div className="panel-body">{children}</div> </div> ); } // Usage — the <p> and <ul> are children <Panel title="Week 11"> <p>React session today</p> <ul><li>Components</li><li>Props</li></ul> </Panel>

4. Lists & Conditional Rendering

Rendering lists with .map()

const courses = [ { id: 1, name: 'Web Programming', credits: 3 }, { id: 2, name: 'Databases', credits: 3 }, { id: 3, name: 'Algorithms', credits: 4 }, ]; function CourseList() { return ( <ul> {courses.map(course => ( // key must be unique and stable — use the id, not the index <li key={course.id}> {course.name} — {course.credits} credits </li> ))} </ul> ); }
⚠️

Always add key: React uses key to identify which items changed. Missing keys causes a console warning and potential rendering bugs. Use a stable unique ID, not the array index.

Conditional rendering

function UserGreeting({ isLoggedIn, username }) { // 1. Ternary — renders one of two options return ( <div> {isLoggedIn ? <h1>Welcome back, {username}!</h1> : <h1>Please log in</h1> } {/* 2. && — renders only when condition is truthy */} {isLoggedIn && <button>Log out</button>} {/* 3. Early return — cleanest for big branches */} </div> ); } // 3. Early return pattern function Dashboard({ isAdmin }) { if (!isAdmin) return <p>Access denied</p>; return <AdminPanel />; }

5. Component Composition

Build complex UIs by composing smaller, single-responsibility components. This keeps each component focused, testable, and reusable.

// Small, focused components function Avatar({ src, alt }) { return <img src={src} alt={alt} style={{ borderRadius: '50%', width: 48 }} />; } function Badge({ text, color = '#0891b2' }) { return ( <span style={{ background: color, color: '#fff', padding: '2px 8px', borderRadius: 4 }}> {text} </span> ); } function StudentCard({ name, studentId, year, avatarUrl }) { return ( <div className="card"> <Avatar src={avatarUrl} alt={name} /> <h3>{name}</h3> <p>ID: {studentId}</p> <Badge text={`Year ${year}`} /> </div> ); } // Composed together in App function App() { return ( <div className="student-list"> <StudentCard name="Amir" studentId="202011234" year={3} avatarUrl="/img/amir.jpg" /> <StudentCard name="Zulfiya" studentId="202012345" year={2} avatarUrl="/img/zulfiya.jpg" /> </div> ); }
✅

Single Responsibility Principle: Each component should do one thing. If a component grows too large, split it into smaller ones. Avatar, Badge, and StudentCard each have a clear, narrow job.

JSX rules

• One root element (or <></>)
• className not class
• self-close: <br />
• JS in {expressions}

Key rule

/* Use stable unique id */
key={item.id}  ✅
key={index}    ⚠️ avoid
