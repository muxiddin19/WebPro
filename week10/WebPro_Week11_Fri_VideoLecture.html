⚛️ What is React?

React is a JavaScript library for building user interfaces — created by Meta (Facebook) and open-sourced in 2013.

The old way (jQuery era)
  • Find a DOM element
  • Manually change its content
  • Hard to keep UI & data in sync
  • Code becomes "spaghetti"
The React way
  • Describe what the UI should look like
  • React figures out the how
  • UI automatically re-renders when data changes
  • Split into small, reusable components
Core idea: Your UI is a function of your data. UI = f(data)

📝 JSX — JavaScript + XML

JSX lets you write HTML-like syntax inside JavaScript. It's NOT HTML — it compiles to React.createElement() calls.

// JSX (what you write)
const element = <h1 className="title">Hello, {'{name}'}</h1>;

// What Babel compiles it to
const element = React.createElement(
  'h1',
  { className: 'title' },
  'Hello, ' + name
);

JSX rules

  • Use className instead of class
  • Use htmlFor instead of for (labels)
  • Self-close empty tags: <img />, <input />, <br />
  • One root element: wrap siblings in <div> or <>…</> (Fragment)
  • JavaScript expressions go inside {'{}'} curly braces

🧩 Functional Components

A React component is just a JavaScript function that returns JSX. The function name must start with a capital letter.

// Simplest possible component
function Greeting() {
  return (
    <div>
      <h1>안녕하세요!</h1>
      <p>Welcome to Web Programming</p>
    </div>
  );
}

// Arrow function form (also common)
const Greeting = () => (
  <div>
    <h1>안녕하세요!</h1>
  </div>
);
Use components like custom HTML tags: <Greeting />

📦 Props — Passing Data to Components

Props (short for properties) are how you pass data from a parent component to a child. They are read-only inside the child.

// Parent passes name as a prop
function App() {
  return (
    <div>
      <ProfileCard name="김민준" role="Frontend Developer" />
      <ProfileCard name="이서연" role="UI Designer" />
    </div>
  );
}

// Child receives props as an object
function ProfileCard({ name, role }) {
  return (
    <div className="card">
      <h2>{name}</h2>
      <p>{role}</p>
    </div>
  );
}
Destructuring { name, role } in the parameter is cleaner than props.name everywhere.

🛡️ Default Props & PropTypes

Default Props

function Avatar({ src, size = 60, alt = 'User avatar' }) {
  return <img src={src} width={size} height={size} alt={alt} />;
}

// size and alt are optional — defaults kick in if omitted
<Avatar src="/kim.jpg" />         // size=60, alt='User avatar'
<Avatar src="/lee.jpg" size={120} /> // size=120, alt='User avatar'

PropTypes (runtime type checking)

import PropTypes from 'prop-types';

ProfileCard.propTypes = {
  name: PropTypes.string.isRequired,
  role: PropTypes.string,
  avatarUrl: PropTypes.string,
};

// Console warning if a required prop is missing
In TypeScript projects you use interfaces instead of PropTypes — but PropTypes is valuable in plain JS.

🏗️ Component Composition

Build complex UIs by composing small components together — like LEGO bricks.

function Avatar({ src, name }) {
  return <img src={src} alt={name} className="avatar" />;
}

function UserInfo({ name, dept }) {
  return (
    <div className="user-info">
      <strong>{name}</strong>
      <span>{dept}</span>
    </div>
  );
}

// Compose both into a larger component
function ProfileCard({ user }) {
  return (
    <div className="profile-card">
      <Avatar src={user.photo} name={user.name} />
      <UserInfo name={user.name} dept={user.dept} />
    </div>
  );
}

👶 The children Prop

props.children is whatever you put between a component's opening and closing tags.

function Card({ title, children }) {
  return (
    <div className="card">
      <h3 className="card-title">{title}</h3>
      <div className="card-body">
        {children}
      </div>
    </div>
  );
}

// Usage — anything inside <Card> becomes children
<Card title="Week 11">
  <p>React Components are awesome!</p>
  <ul>
    <li>Reusable</li>
    <li>Composable</li>
  </ul>
</Card>
The children pattern enables wrapper/layout components — Card, Modal, Sidebar, etc.

📋 Rendering Lists with .map()

Use JavaScript's .map() to render an array of items as JSX. Always provide a unique key prop.

const students = [
  { id: 1, name: '김민준', score: 88 },
  { id: 2, name: '이서연', score: 95 },
  { id: 3, name: '박지호', score: 72 },
];

function StudentList() {
  return (
    <ul>
      {students.map(student => (
        <li key={student.id}>
          {student.name} — {student.score}점
        </li>
      ))}
    </ul>
  );
}
Why are keys required?

React uses keys to identify which items changed, were added, or removed. Without them, React re-renders every item — causing bugs and poor performance. Use unique IDs, never array index (unless the list never re-orders).

🔀 Conditional Rendering

Render different JSX based on a condition using JavaScript operators.

// 1. Ternary operator — renders either A or B
function StatusBadge({ isOnline }) {
  return (
    <span className={isOnline ? 'badge-green' : 'badge-grey'}>
      {isOnline ? 'Online' : 'Offline'}
    </span>
  );
}

// 2. Short-circuit && — renders only if condition is true
function Notification({ hasError, message }) {
  return (
    <div>
      {hasError && <p className="error">{message}</p>}
      <p>Content always renders here.</p>
    </div>
  );
}

// 3. if/else before the return (for complex logic)
function Dashboard({ user }) {
  if (!user) return <p>Please log in.</p>;
  return <h1>Welcome, {user.name}!</h1>;
}

🏆 Putting It Together — Grade Card App

function GradeCard({ student }) {
  const passed = student.score >= 60;
  return (
    <div className="grade-card">
      <h3>{student.name}</h3>
      <p>학번: {student.id}</p>
      <p>점수: {student.score}점</p>
      <span className={passed ? 'pass' : 'fail'}>
        {passed ? '✅ 합격' : '❌ 불합격'}
      </span>
    </div>
  );
}

const roster = [
  { id: '20231001', name: '김민준', score: 88 },
  { id: '20231002', name: '이서연', score: 45 },
];

function GradeBoard() {
  return (
    <main>
      <h1>성적 현황</h1>
      {roster.map(s => <GradeCard key={s.id} student={s} />)}
    </main>
  );
}

⚠️ Common Mistakes to Avoid

❌ Mutating props
function Bad({ items }) {
  items.push('new item'); // WRONG — never mutate props!
  return <ul>{items.map(i => <li>{i}</li>)}</ul>;
}
❌ Lowercase component names
function profileCard() { ... } // Wrong — React treats it as a DOM tag
function ProfileCard() { ... } // Correct
❌ Missing keys in lists
{items.map(item => <li>{item}</li>)}         // Missing key — warning!
{items.map((item, i) => <li key={i}>{item}</li>)} // Index key — risky
{items.map(item => <li key={item.id}>{item.name}</li>)} // Correct

✅ Summary — Key Takeaways

1
Components are JavaScript functions that return JSX. Names start with a capital letter.
2
JSX looks like HTML but compiles to React.createElement(). Use className, not class.
3
Props pass data from parent → child. They are read-only in the child.
4
Default values can be set with ES6 destructuring defaults: { size = 60 }.
5
Composition: build complex UIs by nesting small components. Use children for wrapper patterns.
6
Lists: use .map() + a unique key prop on the outermost element.
7
Conditional rendering: ternary for A/B, && for show/hide, if before return for complex logic.
