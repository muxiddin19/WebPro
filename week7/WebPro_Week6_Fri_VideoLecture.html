Chapter 2

novalidate +
preventDefault()

Two essential tools to take over from the browser

The novalidate Attribute
Step back, browser — JavaScript is handling this
Analogy: Like telling a restaurant: "Don't use your automatic menu recommendations — I'll order myself." novalidate says: browser, step back. My JS is in charge.
HTML
<!-- WITHOUT novalidate: browser takes over --> <form method="post"> <input type="email" required> <button>Submit</button> </form> <!-- WITH novalidate: YOU are in charge --> <form method="post" novalidate id="regForm"> <input type="email" id="email" aria-describedby="err-email"> <span id="err-email"></span> <button>Submit</button> </form>
preventDefault() — Pause the Form
The single most important line in form validation
Analogy: Like a receptionist who intercepts every call — they decide what happens, not the phone. preventDefault() catches the submit event before the browser acts on it.
❌ Without preventDefault
form.addEventListener('submit', (e) => { // Page reloads immediately! // This code never runs. console.log('Never executes'); });
✅ Correct Approach
form.addEventListener('submit', (e) => { e.preventDefault(); // PAUSE the form if (validateAll()) { showSuccess(); // All valid → done! } else { highlightErrors(); // Show what's wrong } });

Chapter 3

The input Event

Real-time feedback on every keystroke

submit vs input — Two Different UX Worlds
When does the user see the error? The answer changes everything.
❌ submit only — user waits until the end
// Only validates when Submit is clicked form.addEventListener('submit', (e) => { e.preventDefault(); if (!sid.value.match(/^\d{9}$/)) { showError('Must be 9 digits'); // User typed 8 fields before seeing this! } });
✅ input event — instant feedback per key
// Validates on EVERY keystroke sid.addEventListener('input', function() { if (/^\d{9}$/.test(this.value)) { markValid(this); // ✅ green border } else { markInvalid(this, // ❌ red border 'Must be exactly 9 digits'); } }); // User sees feedback as they type!

The validity Object
+ Regex

Checking not just IF a field is invalid — but WHY

The validity Object — Built-in Constraint Checks
Every input element has a .validity property — it tells you exactly WHY a field is invalid
JavaScript — validity API
const email = document.getElementById('email'); // HTML5 validity API — built-in checks: email.validity.valueMissing // required + empty email.validity.typeMismatch // bad email format email.validity.tooShort // below minlength email.validity.patternMismatch // pattern fails // Check if ALL constraints pass: email.validity.valid // true only if everything OK // For custom patterns — regex .test(): const sid = document.getElementById('sid'); /^\d{9}$/.test(sid.value) // 9 digits? true/false
validity Properties — At a Glance

Chapter 5

Making Errors
Accessible

ARIA attributes ensure every user — including screen reader users — gets the error

ARIA — aria-invalid, aria-describedby, role=alert
Three attributes that make your validation screen-reader ready
Analogy: aria-describedby is like a footnote number — it points the screen reader from the input to its error note, without changing the visual layout.
HTML — structure
<label for="sid">Student ID</label> <input type="text" id="sid" aria-describedby="err-sid" aria-invalid="false"> <!-- ↑ links to error span ↑ valid state --> <span id="err-sid" role="alert"> <!-- role="alert" → reads immediately --> </span>
JavaScript — set & clear
function markInvalid(input, errSpan, msg) { input.setAttribute( 'aria-invalid', 'true'); // notify AT errSpan.textContent = msg; // role=alert fires → screen reader reads it } function markValid(input, errSpan) { input.setAttribute( 'aria-invalid', 'false'); errSpan.textContent = ''; }
setCustomValidity() — Cross-field Checks
HTML5 has no built-in password confirmation check — setCustomValidity bridges the gap
Key idea: A non-empty string makes the field invalid. An empty string clears the error. Without this, form.checkValidity() won't know about your custom logic.
JavaScript — password confirmation pattern
const pw = document.getElementById('pw'); const pw2 = document.getElementById('pw2'); pw2.addEventListener('input', function() { if (this.value !== pw.value) { // Non-empty string = this field is INVALID this.setCustomValidity('Passwords do not match'); markInvalid(this, err, 'Passwords do not match'); } else { // Empty string = this field is VALID again this.setCustomValidity(''); markValid(this, err); } });
Summary — JS Form Validation Pattern
Everything you need to build production-quality forms
  • ✅
    novalidate disables browser UI — JS takes over validation entirely
  • ✅
    e.preventDefault() pauses the submit — prevents page reload so your code can run
  • ✅

  • ✅

  • ✅
    Regex for custom format checks — /^\d{9}$/ for student ID, etc.
  • ✅

  • ✅
    setCustomValidity() for cross-field checks like password confirmation
