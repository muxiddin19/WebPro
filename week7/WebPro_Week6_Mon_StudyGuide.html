01

Why Forms?

Beginner

Forms are the primary way users send data to a server. Without forms, websites would be one-directional — you can only read, not interact. Every action that changes something on a server uses a form under the hood.

Here are three real-world examples you use every day:

Real-World Form Examples

🔐
Login
Username + Password → Server checks credentials
🔍
Search
Keyword → Server returns matching results
📝
Registration
Name, email, password → New account created
HTML — Google Search Form (simplified)
<!-- The Google search bar is just an HTML form --> <form action="https://www.google.com/search" method="get"> <input type="text" name="q" placeholder="Search Google..."> <button type="submit">Search</button> </form>
✅
Try it! The form above actually works — submitting it would search Google for your text.

Key Points

  • Forms collect user input and send it to a server.
  • Every website interaction that changes data uses a form.
  • HTML provides the structure; CSS styles it; JavaScript validates it.
  • The <form> element wraps all form controls.
02

The <form> Element

Beginner

The <form> element is the container for all form controls. Its two most important attributes are action (where to send the data) and method (how to send it).

HTML — Form Anatomy
<form action="/login" <!-- Where to send data --> method="post" <!-- How to send: GET or POST --> novalidate <!-- Disable built-in validation (use JS) --> > <label for="email">Email</label> <input type="email" id="email" name="email" required> <label for="pw">Password</label> <input type="password" id="pw" name="password" required> <button type="submit">Log In</button> </form>

GET vs POST — The Key Difference

GET METHOD
Data is appended to the URL:
/search?q=javascript&lang=en
  • Visible in browser address bar
  • Can be bookmarked / shared
  • Limited data (~2000 chars)
  • Use for: search, filters
POST METHOD
Data is in the request body:
email=kim@gachon.edu
password=secret123
  • Hidden from address bar
  • Not bookmarkable
  • No size limit (practically)
  • Use for: login, register, submit
⚠️
Analogy: GET is like writing on a postcard — everyone can see it. POST is like sealing a letter in an envelope. Use POST for sensitive data like passwords.

Key Points

  • action — the URL where form data is sent on submit.
  • method="get" — data goes in the URL; good for search.
  • method="post" — data goes in the request body; use for sensitive data.
  • name attribute on inputs — this is the key the server receives.
  • A submit button (type="submit") inside the form triggers submission.
03

Input Types

Beginner

HTML5 introduced many specialized input types. Each type tells the browser what kind of data to expect — the browser adapts its interface (keyboard on mobile), built-in validation, and visual rendering accordingly.

The type attribute is the most important attribute on <input>.

type="text"
Default. Any single-line text.
type="email"
Validates email format. Mobile shows @ keyboard.
type="password"
Masks characters as dots/asterisks.
type="number"
Numeric only. Shows up/down spinner arrows.
type="date"
Date picker. Returns YYYY-MM-DD format.
type="range"
Slider between min and max values.
type="checkbox"
Toggle on/off. Can select multiple.
type="radio"
Same name = one choice only.
<select> — Dropdown
Lets users pick from a predefined list. Not an input, but commonly used with forms.
HTML — All Input Types
<input type="text" placeholder="Any text"> <input type="email" placeholder="name@email.com"> <input type="password" placeholder="Secret..."> <input type="number" min="1" max="10"> <input type="date"> <input type="range" min="0" max="100"> <input type="checkbox" name="agree"> <input type="radio" name="gender" value="m"> <select name="major"> <option value="">-- Select --</option> <option value="cs">Computer Science</option> </select>

Key Points

  • type="email" — browser validates format; mobile shows @ keyboard.
  • type="password" — always masks characters.
  • type="radio" — group with the same name for single selection.
  • type="checkbox" — multiple checkboxes with same name = multiple values.
  • <select> is not an input element but submits like one when given a name.
04

HTML5 Validation Attributes

Intermediate

HTML5 lets you add validation rules directly in the HTML as attributes. When the user clicks Submit, the browser checks these rules and shows error messages for free — no JavaScript needed.

Validation Attributes — Live Demo (try submitting each field empty)

HTML — Validation Attributes
<!-- required: field must not be empty --> <input type="text" required> <!-- minlength / maxlength: text length constraints --> <input type="text" minlength="8" maxlength="20"> <!-- min / max: numeric or date bounds --> <input type="number" min="1" max="100"> <!-- step: acceptable intervals --> <input type="number" step="5" min="0"> <!-- pattern: regular expression the value must match --> <input type="text" pattern="\d{9}" title="Enter your 9-digit student ID">
💡
The title attribute works with pattern to show a helpful error message in the browser's validation tooltip. Always add it when using pattern.

Key Points

  • required — boolean attribute; the field must have a non-empty value.
  • minlength / maxlength — character count bounds for text.
  • min / max — numeric or date bounds.
  • step — allowed increment (e.g., step="5" means 0, 5, 10…).
  • pattern — a regex the full value must match.
  • HTML5 validation runs when a form is submitted. It does NOT run on every keystroke.
05

Labels & Accessibility

Beginner

The <label> element links a text description to an input. This is critical for accessibility: screen readers (used by visually impaired users) announce the label when the input is focused. Without a label, screen reader users hear only "edit text" — they don't know what to type.

There are two ways to associate a label:

HTML — Two Ways to Use Labels
<!-- Method 1: for/id pairing (recommended) --> <label for="username">Username</label> <input type="text" id="username" name="username"> <!-- Method 2: wrap the input inside the label --> <label> Email <input type="email" name="email"> </label> <!-- WRONG: placeholder is NOT a label --> <input type="text" placeholder="Username"> <!-- ❌ not accessible -->

Label Benefit — Click the label text to focus the input!

✓ WITH LABEL (click the text below)
❌ NO LABEL (placeholder only)
Just text (not clickable)
⚠️
Placeholder is NOT a label! Placeholders disappear when the user starts typing, which causes confusion. Always use a proper <label> element and use placeholder only for format hints (e.g., "YYYY-MM-DD").

Key Points

  • <label for="id"> connects to <input id="id"> — they must match exactly.
  • Clicking the label moves focus to the input — important for usability.
  • Screen readers announce the label when the input is focused.
  • Placeholder text is a hint, NOT a substitute for a label.
06

Grouping Fields: <fieldset> & <legend>

Beginner

When a form has many fields, use <fieldset> to group related inputs together, and <legend> to label the group. This helps both sighted users (visible border and group title) and screen reader users (the legend is announced before each field in the group).

HTML — Fieldset & Legend
<form method="post" action="/register"> <fieldset> <legend>Personal Information</legend> <label for="fname">First Name</label> <input type="text" id="fname" name="first_name" required> <label for="lname">Last Name</label> <input type="text" id="lname" name="last_name" required> </fieldset> <fieldset> <legend>Account Details</legend> <label for="reg-email">Email</label> <input type="email" id="reg-email" name="email" required> <label for="reg-pw">Password</label> <input type="password" id="reg-pw" name="password" required> </fieldset> <button type="submit">Register</button> </form>

Live Preview

Personal Information
Account Details

Key Points

  • <fieldset> draws a border around a group of related fields.
  • <legend> provides a visible and accessible label for the group.
  • Screen readers announce the legend text before reading each field in the group.
  • Use fieldsets for long forms: personal info, payment details, preferences, etc.
07

CSS Validation Pseudo-classes

Intermediate

CSS provides special pseudo-classes that match inputs based on their validation state. You can use these to style inputs green/red automatically without JavaScript — the browser updates the state as the user types.

CSS — Validation Pseudo-classes
/* :focus — applied when the input has keyboard focus */ input:focus { border-color: #1a56db; box-shadow: 0 0 0 3px rgba(26, 86, 219, 0.2); outline: none; } /* :valid — applied when the value passes all HTML5 validation */ input:valid { border-color: #16a34a; /* green */ } /* :invalid — applied when the value fails validation */ input:invalid { border-color: #dc2626; /* red */ } /* :placeholder-shown — only while placeholder is visible */ /* (i.e., the field is empty) — combine with :invalid to avoid */ /* showing red on an untouched empty required field */ input:invalid:not(:placeholder-shown) { border-color: #dc2626; background: #fee2e2; } input:valid:not(:placeholder-shown) { border-color: #16a34a; background: #dcfce7; }

Live Demo — Type in the fields to see CSS validation states

:valid
Green border + background = correct value
:invalid (typed)
Red border + background = wrong value
:placeholder-shown
No styling while empty

Key Points

  • :focus — shown when element has keyboard focus.
  • :valid — matches when value satisfies all validation constraints.
  • :invalid — matches when value fails any constraint.
  • :placeholder-shown — true when the placeholder is visible (field is empty).
  • Combine: :invalid:not(:placeholder-shown) to avoid red on untouched fields.
