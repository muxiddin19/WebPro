JavaScript Form Validation

9 topics · 3 live-code exercises · builds on Monday's HTML5 foundation

💡
What we're doing today HTML5 validation catches simple errors but cannot compare two fields, show real-time feedback, or provide custom messages in Korean. JavaScript gives us complete control. All exercises build toward the homework: making Monday's registration form fully interactive.
01

Limits of HTML5 Validation

Beginner

HTML5 validation is great for simple cases, but it has hard limits. When those limits are hit, you need JavaScript.

What HTML5 CANNOT Do

PROBLEM 1
Compare two fields
HTML5 cannot check "password" == "confirm password"
PROBLEM 2
Real-time feedback
HTML5 only validates on submit, not as you type
PROBLEM 3
Custom error messages
Browser validation messages are in the OS language, cannot be customized
PROBLEM 4
Remote validation
Cannot check "is this email already registered?" without a server call

Key Points

  • HTML5 validation = free, fast, no code needed — but very limited.
  • JavaScript validation = full control, custom rules, real-time UX.
  • Best practice: use both — HTML5 for basic rules, JS for advanced ones.
  • Add novalidate to the <form> when you take over validation with JS.
02

event.preventDefault()

Beginner

When a form is submitted, the browser's default behavior is to navigate to the action URL (or reload the page). event.preventDefault() stops this, letting your JavaScript take over.

This is the first line of every JS validation handler.

JavaScript — Intercept Form Submit
const form = document.querySelector('#my-form'); form.addEventListener('submit', (e) => { e.preventDefault(); // ← STOP the page reload! // Now run your own validation const email = document.querySelector('#email').value; if (!email) { showError('Email is required'); return; // stop here } // All good — submit programmatically or via fetch() console.log('Form is valid! Sending...'); });

Live Demo — preventDefault in action

This form would normally reload the page when submitted. Click "Submit" to see our JS intercept it instead.

← Click Submit and watch what happens here (page does NOT reload)

Key Points

  • Listen on the 'submit' event of the <form> element, not the button.
  • e.preventDefault() must be called before any async code.
  • Without preventDefault(), the page reloads even if you have other code below.
  • The event object e also has e.target — the form element itself.
03

checkValidity()

Intermediate

checkValidity() is a browser built-in that runs all HTML5 validation rules programmatically. Call it on an individual input to check just that field, or on the whole form to check every field.

JavaScript — checkValidity()
const emailInput = document.querySelector('#email'); const form = document.querySelector('#my-form'); // Check a single field if (!emailInput.checkValidity()) { console.log('Email is invalid'); console.log(emailInput.validity.valid); // false console.log(emailInput.validity.valueMissing); // true if empty + required console.log(emailInput.validity.typeMismatch); // true if bad email format } // Check the entire form (returns false if ANY field is invalid) if (!form.checkValidity()) { console.log('Form has errors'); } // The .validity property is always there — no need to call checkValidity() first console.log(emailInput.validity.valid); // true or false right now

Live Demo — check validity as you type

Click the button to check validity

Key Points

  • input.checkValidity() returns true or false.
  • input.validity is a ValidityState object with detailed properties.
  • input.validity.valid — quick check: is everything valid?
  • form.checkValidity() — checks ALL fields in the form.
  • Calling checkValidity() does NOT display any UI — it only returns a boolean.
04

The validity Object

Intermediate

Every input has a validity property — a ValidityState object with boolean properties that describe exactly why an input is invalid. Use this to show specific, helpful error messages.

ValidityState Properties

PropertyTrue when...Triggered by attribute
valueMissingField is empty and has requiredrequired
typeMismatchValue doesn't match the input type formattype="email" etc.
patternMismatchValue doesn't match the regex patternpattern="..."
tooShortValue is shorter than minlengthminlength="n"
tooLongValue is longer than maxlengthmaxlength="n"
rangeUnderflowNumber is below minmin="n"
rangeOverflowNumber is above maxmax="n"
stepMismatchNumber doesn't fit the step intervalstep="n"
customErrorsetCustomValidity() was called with a non-empty stringJS only
validAll constraints pass (all above are false)—
JavaScript — Using validity Properties for Custom Messages
function getError(input) { const v = input.validity; if (v.valueMissing) return 'This field is required.'; if (v.typeMismatch) return 'Please enter a valid email address.'; if (v.tooShort) return `Minimum ${input.minLength} characters.`; if (v.patternMismatch) return input.title || 'Invalid format.'; if (v.rangeUnderflow) return `Minimum value is ${input.min}.`; if (v.rangeOverflow) return `Maximum value is ${input.max}.`; return ''; }

Key Points

  • validity.valid is true only when ALL other properties are false.
  • Check specific properties to give targeted error messages (not just "invalid").
  • Template literals (`Minimum ${input.minLength} characters`) let you include the actual constraint value in the message.
05

setCustomValidity()

Intermediate

setCustomValidity(message) sets a custom error on an input, making it invalid regardless of its value. Pass an empty string '' to clear the error. This is how you show a browser tooltip with your own message.

JavaScript — setCustomValidity()
const passwordInput = document.querySelector('#password'); const confirmInput = document.querySelector('#confirm'); confirmInput.addEventListener('input', () => { if (confirmInput.value !== passwordInput.value) { // Mark the field as invalid with a custom message confirmInput.setCustomValidity('Passwords do not match.'); } else { // Clear the custom error (field becomes valid again) confirmInput.setCustomValidity(''); } }); // After setCustomValidity(), validity.customError is true // and validity.valid is false — until you clear it with ''
⚠️
Always clear it! If you set a custom validity and then the user fixes the input, you must call setCustomValidity('') to clear the error. If you forget, the field stays invalid forever.

Key Points

  • input.setCustomValidity('message') — marks field as invalid, sets message for browser tooltip.
  • input.setCustomValidity('') — clears the custom error (field returns to its natural validity state).
  • After setting, input.validity.customError is true and input.validity.valid is false.
  • The browser shows this message in its native validation tooltip on submit.
06

Real-time Feedback with the "input" Event

Intermediate

The 'input' event fires every time the field's value changes (on every keystroke). Combined with a function that checks validity and updates error messages, this creates live feedback as the user types — much better UX than waiting for submit.

JavaScript — Real-time Validation Pattern
const emailInput = document.querySelector('#email'); const emailError = document.querySelector('#email-error'); emailInput.addEventListener('input', () => { const v = emailInput.validity; if (v.valid) { emailError.textContent = ''; // clear error emailInput.classList.remove('error'); emailInput.classList.add('ok'); } else { if (v.valueMissing) emailError.textContent = 'Email is required.'; if (v.typeMismatch) emailError.textContent = 'Not a valid email format.'; emailInput.classList.add('error'); emailInput.classList.remove('ok'); } });

Live Demo — real-time email validation

Key Points

  • 'input' fires on every keystroke — use it for live feedback.
  • 'change' fires only when focus leaves the field — use for less aggressive validation.
  • Always show errors only after the user has started typing. Don't mark empty required fields red immediately.
  • Pattern: read input.validity → update error message → update CSS class.
07

Regex Patterns in JavaScript

Intermediate

Regular expressions (regex) are patterns that describe a set of strings. In JavaScript, create them with /pattern/flags syntax, then test a string with regex.test(string). Regex is more powerful than HTML pattern — you can combine multiple checks, use logical OR (|), and add your own logic.

JavaScript — Common Validation Regexes
// Korean student ID: exactly 9 digits const studentIdRegex = /^\d{9}$/; studentIdRegex.test('202112345'); // true studentIdRegex.test('20211234'); // false (8 digits) studentIdRegex.test('2021abc12'); // false (letters) // Email: basic pattern (HTML5 type="email" is usually enough) const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/; // Korean phone: 010-XXXX-XXXX or 02-XXX-XXXX const phoneRegex = /^(010|011|016|017|018|019)-\d{3,4}-\d{4}$/; // Password strength: at least 8 chars, one uppercase, one number const strongPw = /^(?=.*[A-Z])(?=.*\d).{8,}$/; // Regex syntax cheat sheet: // ^ = start of string // $ = end of string // \d = any digit (0-9) // \s = any whitespace // {9} = exactly 9 times // {3,4} = 3 to 4 times // [A-Z] = any uppercase letter // (?=...) = lookahead (condition, not consumed)

Key Points

  • /^pattern$/ — anchors with ^ (start) and $ (end) ensure the whole string must match.
  • \d{9} — exactly nine digits.
  • regex.test(string) — returns true or false.
  • In HTML pattern attribute, write the regex WITHOUT / /; in JS, wrap with / /.
08

Password Confirmation

Intermediate

Comparing two fields is a classic JavaScript task that HTML5 cannot do. The pattern: listen on the confirm field's 'input' event, compare its value to the password field, and use setCustomValidity() to mark it invalid if they don't match.

JavaScript — Password Confirmation Pattern
const pw = document.querySelector('#password'); const confirm = document.querySelector('#confirm'); const pwErr = document.querySelector('#pw-error'); const cfmErr = document.querySelector('#cfm-error'); // Validate password strength on every keystroke pw.addEventListener('input', () => { if (pw.value.length < 8) { pwErr.textContent = 'Password must be at least 8 characters.'; } else { pwErr.textContent = ''; } // Re-check confirm if already typed if (confirm.value) checkConfirm(); }); function checkConfirm() { if (confirm.value !== pw.value) { confirm.setCustomValidity('Passwords do not match.'); cfmErr.textContent = 'Passwords do not match.'; } else { confirm.setCustomValidity(''); cfmErr.textContent = ''; } } confirm.addEventListener('input', checkConfirm);

Live Demo — Password Confirmation

Key Points

  • Listen on the confirm field AND re-validate when the password field changes.
  • Use setCustomValidity('...') so browser's form submission also catches the mismatch.
  • Always display a visible error message in your own element, not just the browser tooltip.
09

ARIA & Accessibility

Intermediate

When error messages are added dynamically by JavaScript, screen readers don't automatically notice them. ARIA attributes tell screen readers about these dynamic changes.

HTML + JavaScript — ARIA Accessible Errors
<!-- 1. Link each error span to its input with aria-describedby --> <div> <label for="email">Email</label> <input type="email" id="email" name="email" aria-describedby="email-error" aria-required="true"> <span id="email-error" role="alert" aria-live="polite"></span> </div> // 2. When invalid, also set aria-invalid=true on the input function showError(input, errorEl, msg) { errorEl.textContent = msg; input.setAttribute('aria-invalid', 'true'); } function clearError(input, errorEl) { errorEl.textContent = ''; input.setAttribute('aria-invalid', 'false'); }

ARIA Attributes Summary

aria-describedby="id"
Links the input to its error message element. Screen reader reads the error after the input's label.
aria-invalid="true/false"
Tells screen readers whether the field currently has an error. Set to "true" when showing error.
aria-live="polite"
On the error element: screen reader announces changes to this element when it's not busy.
role="alert"
Makes the element an alert region — the message is announced immediately when content changes.

Key Points

  • aria-describedby="error-id" links an input to its error message.
  • aria-invalid="true" tells screen readers the field has an error.
  • aria-live="polite" on the error element announces changes when the user pauses.
  • role="alert" announces immediately (useful for critical errors).
  • These attributes do nothing visual — they only affect assistive technologies.

Prevent Submit & Show Custom Error

Beginner

  • Listen for the form's 'submit' event
  • Call e.preventDefault() to stop the page reload
  • Check if the username field is empty
  • If empty: show "Username is required" in the error span
  • If not empty: show "Welcome, [name]!" in a success message
Hint:
form.addEventListener('submit', (e) => { e.preventDefault(); ... })
Check: if (uname.value.trim() === '') { error.textContent = 'Username is required'; }
Else: success.textContent = 'Welcome, ' + uname.value + '!';
Solution
const form = document.querySelector('#login-form'); const uname = document.querySelector('#uname'); const errEl = document.querySelector('#uname-error'); const success = document.querySelector('#success-msg'); form.addEventListener('submit', (e) => { e.preventDefault(); const val = uname.value.trim(); if (!val) { errEl.textContent = 'Username is required.'; success.textContent = ''; } else { errEl.textContent = ''; success.textContent = `Welcome, ${val}!`; } });
E2

Real-time Email Validation

Intermediate
Task: Add a real-time 'input' event listener on the email field that:
  • Only shows errors after the user has typed something (not on empty)
  • Shows "Email is required" if field is empty after being typed
  • Shows "Not a valid email format" if validity.typeMismatch is true
  • Adds class valid-ok when valid and valid-err when invalid
  • Removes both classes when the field is empty again
Hint: Structure your if/else like this: if (isEmpty) { /* reset */ } else if (v.valid) { /* show OK */ } else { /* show error */ } To clear classes: emailInput.classList.remove('valid-ok', 'valid-err')
Solution
emailInput.addEventListener('input', () => { const v = emailInput.validity; const isEmpty = emailInput.value === ''; if (isEmpty) { emailInput.classList.remove('valid-ok', 'valid-err'); errEl.textContent = ''; okEl.textContent = ''; } else if (v.valid) { emailInput.classList.add('valid-ok'); emailInput.classList.remove('valid-err'); errEl.textContent = ''; okEl.textContent = '✓ Valid email!'; } else { emailInput.classList.add('valid-err'); emailInput.classList.remove('valid-ok'); okEl.textContent = ''; if (v.valueMissing) errEl.textContent = 'Email is required.'; if (v.typeMismatch) errEl.textContent = 'Not a valid email format.'; } });
E3

Password Confirmation with ARIA

Challenge
Task: Build a password + confirm form with full JS validation and ARIA:
  • Live validation on the password field: must be ≥ 8 chars
  • Live validation on confirm: must match the password field exactly
  • Use setCustomValidity() on the confirm field
  • Add aria-describedby linking inputs to their error spans
  • Set aria-invalid="true" when invalid, "false" when valid
  • Both error spans should have aria-live="polite"
Hint:
For aria: pw.setAttribute('aria-invalid', 'true') / 'false'
For setCustomValidity: cfm.setCustomValidity('Passwords do not match.') — clear with cfm.setCustomValidity('')
Call checkCfm() at the end of the pw listener too.
Solution
pw.addEventListener('input', () => { if (pw.validity.tooShort || pw.validity.valueMissing) { pw.classList.add('err'); pw.classList.remove('ok'); pw.setAttribute('aria-invalid', 'true'); pwErr.textContent = 'Password must be at least 8 characters.'; } else { pw.classList.add('ok'); pw.classList.remove('err'); pw.setAttribute('aria-invalid', 'false'); pwErr.textContent = ''; } if (cfm.value) checkCfm(); }); function checkCfm() { if (cfm.value !== pw.value) { cfm.setCustomValidity('Passwords do not match.'); cfm.classList.add('err'); cfm.classList.remove('ok'); cfm.setAttribute('aria-invalid', 'true'); cfmErr.textContent = 'Passwords do not match.'; } else { cfm.setCustomValidity(''); cfm.classList.add('ok'); cfm.classList.remove('err'); cfm.setAttribute('aria-invalid', 'false'); cfmErr.textContent = ''; } } cfm.addEventListener('input', checkCfm); form.addEventListener('submit', (e) => { e.preventDefault(); if (pw.validity.valid && cfm.validity.valid) { alert('Account created successfully!'); } });
