The <form> Element
The container that wraps all your input fields — two attributes matter most
<form action="/login" ← WHERE to send data method="post" ← HOW to send: GET or POST > <label for="email">Email</label> <input type="email" id="email" name="email" required> <label for="pw">Password</label> <input type="password" id="pw" name="password" required> <button type="submit">Log In</button> </form>
GET vs POST
Two ways to send form data — choose based on security and purpose
❌ DO NOT use GET for sensitive data
Like a postcard: everyone who handles it can read what's written on it.
Data is visible in the URL:
/login?email=kim@gachon.edu&password=secret123
✓ Use for: search, filters, bookmarkable pages
✓ POST — use for sensitive data
Like a sealed envelope: only the recipient can read the contents.
Data is in the request body (hidden):
Request body:
email=kim@gachon.edu
password=secret123
✓ Use for: login, register, payment, any form that changes data
Input Types — Part 1
The type attribute controls appearance, keyboard (mobile), and built-in validation
/* text — anything goes */ <input type="text" placeholder="Any text"> /* email — validates @ and domain */ <input type="email" placeholder="name@site.com"> /* password — masks characters */ <input type="password" placeholder="Secret"> /* number — spinner, min/max work here */ <input type="number" min="1" max="100">
Input Types — Part 2
Specialized types give you date pickers, sliders, checkboxes, radios, and dropdowns
<input type="date"> <input type="range" min="0" max="100"> /* checkbox — multiple can be selected */ <input type="checkbox" name="html"> HTML <input type="checkbox" name="css"> CSS /* radio — same name = one choice only */ <input type="radio" name="day" value="mon"> Mon <input type="radio" name="day" value="fri"> Fri <select name="major"> <option>Computer Science</option> </select>
Validation Attributes: required & pattern
Add rules directly in HTML — the browser enforces them for free on submit
required & pattern
/* required: field must not be empty */ <input type="text" required> /* pattern: regex the value must match */ <input type="text" pattern="\d{9}" title="9-digit student ID" required> /* type="email" has built-in pattern */ <input type="email" required>
What the user sees
Browser tooltip shown when invalid
Please fill in this field.
Please match the requested format.
Validation Attributes: min, max, maxlength, step
Constrain numeric ranges and text lengths with HTML attributes alone
/* minlength / maxlength for text */ <input type="text" minlength="8" maxlength="20"> /* min / max for numbers and dates */ <input type="number" min="1" max="100"> /* step: only multiples of 5 allowed */ <input type="number" step="5" min="0" max="100">
!
These only validate on submit. For real-time feedback, you'll need JavaScript (Friday's class).
Labels — Why They Matter
Skipping labels is one of the most common and harmful accessibility mistakes
❌ WITHOUT LABEL (placeholder only)
  • Clicking "Email address" text does nothing
  • Placeholder disappears when you type
  • Screen readers say "edit text" — no context
  • Small click target (just the input box)
✓ WITH LABEL (for/id pairing)
  • Clicking "Full Name" focuses the input
  • Label stays visible while typing
  • Screen readers announce label on focus
  • Larger click target = better mobile UX
CSS :valid and :invalid
Style inputs automatically based on their validation state — no JavaScript needed
/* focus: blue ring on active field */ input:focus { border-color: #1a73e8; box-shadow: 0 0 0 3px rgba(26,115,232,.2); } /* valid + typed → green */ input:valid:not(:placeholder-shown) { border-color: #16a34a; background: #f0fdf4; } /* invalid + typed → red */ input:invalid:not(:placeholder-shown) { border-color: #dc2626; background: #fef2f2; }
Live result — type into the fields
!
:not(:placeholder-shown) prevents showing red on an empty, untouched field.
Fieldset & Legend
Group related fields with a visible border and accessible label
<form method="post"> <fieldset> <legend>Personal Info</legend> <label for="fn">First Name</label> <input type="text" id="fn" required> <label for="ln">Last Name</label> <input type="text" id="ln" required> </fieldset> <fieldset> <legend>Account Details</legend> <label for="em">Email</label> <input type="email" id="em" required> </fieldset> </form>
Output
Personal Info
Account Details
✓
Screen readers announce the legend text before each field. Essential for long forms.
5 Common Mistakes
Every mistake below has been made by millions of developers — learn them now
  • 🏷️
    Missing <label>
    Using only placeholder="Username" — placeholders disappear on focus and are invisible to screen readers. Always add <label for="id">.
  • 📮
    Wrong method for passwords
    Using method="get" on a login form — your password appears in the URL! Always use method="post" for sensitive data.
  • 📋
    Forgetting required
    Building a form without required on any field — the form submits with everything empty. Add required to every mandatory field.
  • 🔤
    Regex typo in pattern
    pattern="d{9}" instead of "\d{9}" — missing the backslash means it matches the letter "d" nine times, not digits.
  • 📍
    Placeholder as substitute for label
    Placeholder text is a hint about format (e.g., "YYYY-MM-DD"), not a label. When the user types, they lose the context of what the field is for.
