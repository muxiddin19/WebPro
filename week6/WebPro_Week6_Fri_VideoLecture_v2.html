The problem with old JavaScript & the new solution

Ch.1 · Why Fetch
Websites Are Not Islands
Almost every modern website gets data from somewhere else
🌤️
Weather Apps
Pull live data from a weather server API
😂
Joke Apps
Fetch a random joke from a joke API
📰
News Sites
Load article headlines without refreshing the page
🛒
Shopping Sites
Update cart totals and product info dynamically
Key idea: Our JavaScript code needs to "call" another server, wait for the answer, then use the data — all without reloading the page.
Ch.1 · Why Fetch
Before fetch() — The Old Way
XMLHttpRequest was powerful but very hard to read
❌ OLD WAY (XMLHttpRequest)
const xhr = new XMLHttpRequest();
xhr.open('GET', url);
xhr.onload = function() {
  if (xhr.status === 200) {
    const data = JSON.parse(xhr.responseText);
    // use data here
  }
};
xhr.send();
✓ NEW WAY (fetch + async/await)
async function loadData() {
  const res = await fetch(url);
  const data = await res.json();
  // use data here
}
Why it matters: fetch() + async/await makes network code as easy to read as normal synchronous code.
Chapter 2 of 5

The Promise

JavaScript's way of saying "I'll get back to you"

Ch.2 · Promise
What Is a Promise?
A placeholder for a value that hasn't arrived yet
Café analogy: When you order at a café, they give you a receipt ticket. That ticket is the Promise — you don't have the coffee yet, but you WILL get it (or they'll tell you they ran out). You don't wait frozen at the counter; you sit down and do other things.
⏳
PENDING
Request is in flight. Waiting for the server to respond.
✅
FULFILLED
Server responded successfully. The data is ready.
❌
REJECTED
Something went wrong — no internet, server crashed, timeout.
Ch.2 · Promise
fetch(url) Returns a Promise
The data is NOT ready yet when fetch() returns
// This runs IMMEDIATELY — before the server responds
const promise = fetch('https://v2.jokeapi.dev/joke/Programming');

console.log(promise); // → Promise { <pending> }
1
fetch() returns a Promise object RIGHT AWAY
JavaScript does not wait for the server. It immediately moves on.
2
The Promise starts in "Pending" state
It means: "I've sent the request — I'm waiting for the answer."
3
Later, the Promise resolves to a Response object
The Response contains the HTTP status code, headers, and body.
Chapter 3 of 5

async / await

Making asynchronous code look and feel synchronous

Ch.3 · async/await
The Four Steps of a Fetch Request
Our code → Internet → Server → Back to our code
Your JS Code
calls fetch(url)
① send request
Internet
packets travel
② arrives
Joke Server
processes request
③ sends reply
Browser
receives response
!
Steps ①②③ take 50–500 milliseconds
During that wait, your JavaScript continues running other code — it doesn't freeze. await is what makes your function pause and wait at the right moment.
Ch.3 · async/await
The async Keyword
Any function that uses await must be declared async
❌ This FAILS
function loadJoke() {
  // ERROR: await only
  // works inside async
  const res = await fetch(url);
}
✓ This WORKS
async function loadJoke() {
  // OK: function is async
  const res = await fetch(url);
  const data = await res.json();
}
Rule to remember: async and await always come in a pair. No async → no await. They are like left shoe and right shoe.
Ch.3 · async/await
Why We Need TWO await Calls
Getting the Response is step 1. Reading its body is step 2.
async function loadJoke() {
  // Step 1: Wait for the server to RESPOND (headers arrive)
  const res = await fetch('https://v2.jokeapi.dev/joke/Programming');
  // res = Response { status: 200, ok: true, ... }

  // Step 2: Wait for the BODY to be fully downloaded & parsed
  const data = await res.json();
  // data = { setup: "Why ...", punchline: "Because ..." }

  console.log(data.setup);
}
1
First await = headers ready
Status code (200/404/500) and other headers arrive first.
2
Second await = body ready
The JSON body streams in and is parsed. This can take extra time for large responses.
Ch.3 · async/await
The Hidden Danger: res.ok
fetch() does NOT throw an error for 404 or 500 — you must check
⚠ Common Beginner Mistake
fetch() only rejects (throws) for network failures — no internet, DNS error, timeout.
HTTP error codes like 404 (Not Found) or 500 (Server Error) are treated as successful responses!

Chapter 4 of 5

Error Handling

try / catch / finally — what to do when things go wrong

Ch.4 · Error Handling
try / catch / finally
The professional pattern for safe fetch requests
async function loadJoke() {
  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error(`HTTP error: ${res.status}`);
    const data = await res.json();
    showJoke(data); // ← happy path
  } catch (err) {
    console.error('Failed:', err.message);
    showError('Could not load joke 😔');
  } finally {
    hideSpinner(); // ← ALWAYS runs
  }
}
try
Runs the risky code. If anything throws, jumps to catch.
catch
Catches ANY error (network failure OR our manual throw).
finally
ALWAYS runs — perfect for hiding loading spinners.
Ch.4 · Error Handling
Understanding finally
It runs no matter what — success, error, or exception
Real-life analogy: When you leave your house, you lock the door whether your trip was successful (you found what you needed) or a failure (the shop was closed). Locking the door is "finally" — it happens regardless.
✓
Loading spinner / skeleton screen
Show a spinner before fetch(), hide it in finally — whether the data arrived or an error occurred, the spinner always disappears.
✓
Re-enabling submit buttons
Disable a button while submitting a form, re-enable it in finally — even if the server returned an error.
✓
Logging and analytics
Record how long the request took, regardless of outcome.
Chapter 5 of 5

Complete Patterns

POST requests, real-world code, and best practices

Ch.5 · Complete Patterns
Sending Data: POST Requests
Add a second argument to fetch() with method, headers, and body
async function saveScore(studentId, score) {
  try {
    const res = await fetch('/api/scores', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ studentId, score }),
    });
    if (!res.ok) throw new Error('Save failed');
    const result = await res.json();
    console.log('Saved!', result);
  } catch (err) { console.error(err); }
}
method
'GET', 'POST', 'PUT', 'DELETE' — GET is the default.
body
Must be a string — use JSON.stringify() to convert objects.
Ch.5 · Complete Patterns
The Complete Professional Pattern
Everything together — the pattern to memorize
async function loadJoke() {
  showSpinner(); // show loading indicator
  try {
    // 1. Send the request — await the server's headers
    const res = await fetch('https://v2.jokeapi.dev/joke/Programming');

    // 2. Check HTTP status (fetch never throws for 404!)
    if (!res.ok) throw new Error(`Server returned ${res.status}`);

    // 3. Await the body — parse JSON
    const data = await res.json();

    // 4. Use the data ✓
    document.getElementById('setup').textContent = data.setup;
    document.getElementById('punchline').textContent = data.punchline;
  } catch (err) {
    document.getElementById('error').textContent = 'Could not load 😔';
  } finally {
    hideSpinner(); // always hide the spinner
  }
}
Summary: 7 Things to Remember
The complete mental model for Fetch API
🚀
fetch(url)
Sends a GET request and returns a Promise immediately.
⏳
Promise 3 States
Pending → Fulfilled or Rejected. Always starts as Pending.
🔑
async function
Required before any function that uses await inside.
⏸️
await pauses...
Only the current async function — not the whole page.
2️⃣
Two awaits
First for headers (res), second for body (res.json()).
⚠️
Check res.ok
404/500 do NOT throw! Always check res.ok yourself.
🛡️
try / catch / finally
try: happy path · catch: handle all errors · finally: cleanup code (hide spinner) that ALWAYS runs.
