THE PROBLEM FETCH() SOLVES
What problem does fetch() solve?
😫
Old way: To load new data, the ENTIRE page had to reload. Every time. Slow, annoying, white flash.
✨
New way (fetch): Load data from the internet in the background. Only update the part that changed. Page never reloads.
🌍
You see this everywhere: Google Maps, YouTube comments, weather widgets, chat apps. All use fetch().
💡
Technical name: AJAX — Asynchronous JavaScript And XML (though today we use JSON, not XML).

Analogy

Like sending a text message 📱 — you hit send and put your phone down. You don't stand frozen waiting for a reply. When the reply arrives, your phone buzzes. await is the "waiting for a reply" part.

THE CODE
fetch() — the complete pattern
async function loadJoke() {
  const res  = await fetch('https://official-joke-api.appspot.com/random_joke');
  const data = await res.json();
  document.getElementById('setup').textContent = data.setup;
  document.getElementById('punch').textContent = data.punchline;
}
5 lines. That is all you need to load data from the internet and display it.
PROMISES
fetch() returns a Promise 🎫
☕ Café analogy

Order coffee → get a paper cup with your name (Promise → Pending). 2 minutes later: coffee ready (Promise → Fulfilled) OR "Sorry, out of oat milk" (Promise → Rejected).

⏳

Pending

Request is in flight. Waiting for the server to respond.

✅

Fulfilled

Success! Server sent data. Your .then() or await runs now.

❌

Rejected

Something failed. Your .catch() or try/catch runs.

THE TWO KEYWORDS
async
Put this BEFORE the function name
async function myFn() { ... }
Meaning: "This function uses the internet. It can wait for Promises."
await
Put this BEFORE every Promise
const res = await fetch(url);
Meaning: "Wait here until this Promise resolves. But let the page keep running."
📌
Rule: You can only use await INSIDE an async function. One requires the other.
.then() vs async/await
Two ways to write the same thing

Old style — .then() chains

fetch('/api/joke')
  .then(res => res.json())
  .then(data => {
    show(data);
  })
  .catch(err => {
    error(err);
  });

✨ New style — async/await

async function getJoke() {
  const res  = await fetch('/api/joke');
  const data = await res.json();
  show(data);
}
💡 They are 100% identical in behaviour. async/await is just easier to read — like reading a recipe from top to bottom instead of following a chain of instructions.
⚠️ IMPORTANT GOTCHA
404 does NOT throw an error!

⚠️ The most common beginner mistake

fetch() only REJECTS (throws) when your internet is completely down.
If the server returns 404 or 500, fetch() still RESOLVES as success.
You MUST check response.ok yourself and throw your own error.

const res = await fetch(url);
// ← Always add this check! Never skip it.
if (!res.ok) throw new Error(`HTTP ${res.status}`);
          ↑ true for 200-299    ↑ e.g. "HTTP 404"
ERROR HANDLING
try / catch / finally
async function loadData(url) {
  showSpinner();          // show loading first
  try {                     // attempt the main code
    const res  = await fetch(url);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const data = await res.json();
    render(data);           // success! show the data
  } catch (err) {          // something went wrong
    showError(err.message);
  } finally {             // ALWAYS runs
    hideSpinner();          // hide loading either way
  }
}

SUMMARY
6 things to remember
  • fetch(url) — sends HTTP GET, returns a Promise immediately
  • await — pauses the function (NOT the page) until a Promise resolves
  • res.json() — parses response body as JSON — also returns a Promise
  • res.ok — false for 404/500. You must check this — fetch() will NOT throw for you
  • async — required before any function that uses await
  • finally — always runs after try or catch — use it to hide spinners
