🎯 Quick Answers

What does the proposal need?
5–7 slides covering your team, concept, features, tech stack, wireframes & timeline
Is it just slides we submit?
No — four deliverables: slides (PDF), video, source code, and a deployed page that links everything. All inside your GitHub repo.
Must there be a video presentation?
YES — mandatory. Record a 2–3 min video walking through your proposal. We may not have time for every team to present live in class.
When is it due?
Sunday October 25 — midnight. That's this Sunday. In-class presentations are Monday Nov 3 (Week 10).

📋 Required Slide Contents

You need to cover all 7 items below. You can combine some onto one slide — quality matters more than quantity.

01

Team Introduction Required

  • Team name (creative but professional)
  • All member names + student IDs
  • GitHub username of every member
  • Role per person: Designer / Lead Developer / API Integration / QA & Testing
02

Project Concept Required

  • Project title
  • 2–3 sentence description — what does it do?
  • What problem does it solve?
  • Who are the target users?
03

Core Features Required

  • List 3–5 specific features — be concrete, not vague
  • Mark each as MVP (must-have) or Bonus
  • ❌ Bad: "good UI"  ✅ Good: "filter results by genre using a dropdown"
  • ❌ Bad: "fast loading"  ✅ Good: "lazy-load search results with fetch()"
04

Technology Stack Required

  • HTML / CSS / JavaScript (always required)
  • External API name + base URL (e.g. OpenLibrary, OpenWeatherMap, TMDB)
  • Any libraries: Bootstrap, Chart.js, Axios, etc.
  • Your team GitHub repository URL — must exist before Nov 3
05

UI Wireframes / Mockups Required

  • At least 2 key screens: homepage + one main feature page
  • Hand-drawn is fine — take a photo and insert it
  • Figma, draw.io, or Canva are also fine
  • Show: where is the search bar? where do results appear? what does a card look like?
06

Project Timeline Required

  • Week 10 (Nov 3–9): Finalize design, connect API, basic page structure
  • Week 11 (Nov 10–16): Core features development
  • Week 12 (Nov 17–23): Complete all MVP features, start polishing
  • Week 13 (Nov 24–30): Code review, bug fixing, prepare presentation
  • Week 14 (Dec 1–7): Final presentation & demo
07

GitHub Repository Setup Bonus +5 pts

  • Create the team repo before Nov 3 (get extra credit)
  • Add a README.md with project name, team, and description
  • Invite all team members as collaborators
  • Add a .gitignore that excludes .env files (protect API keys!)

❓ Frequently Asked Questions

Can we use a framework like React or Vue?
For the core project: plain HTML / CSS / JavaScript only. You may use CSS libraries like Bootstrap or Tailwind CSS, and JS utility libraries like Chart.js, Axios, or Swiper. No React, Vue, or Angular.
Which APIs are recommended?
Any free public API works. Popular choices: OpenLibrary (books), OpenWeatherMap (weather, free key), TMDB (movies), REST Countries (countries, no key needed), NASA APOD (astronomy, free key), PokéAPI (Pokémon, no key). Avoid APIs that require payment or credit card.
How do I protect my API key from GitHub?
Store the key in a .env file, add .env to your .gitignore, and never commit it. For GitHub Pages (a public server), you can include the key directly in the JS file for now — just use a free-tier key with low rate limits. Never use a paid API key in client-side code.
Can we build a game instead of a web app?
Yes — as long as it uses an external API for real data and has at least 3 interactive JavaScript features. A trivia game using an API for questions, for example, is completely fine.
What if our idea changes after the proposal?
Minor changes (removing a bonus feature, swapping one API for another) are fine — just mention it in your Week 12 progress. Major pivots (completely different concept) require professor approval. The proposal sets expectations, not a binding contract.
Can we work alone or in pairs?
No — teams must have 3–4 members. If you don't have a team by October 31, email the professor and one will be assigned. Pairs will be asked to add a third member.
What tool should we use to record the video?
OBS Studio (free, Windows/Mac/Linux) — start a new recording, add your screen as a source, hit Record while you advance your slides and speak. Loom (free, browser extension) is even simpler. Zoom local recording also works — start a meeting alone, share your screen, record, end the meeting. On Mac, QuickTime Player → New Screen Recording is built-in and free.
How do I host the video so the professor can watch it on my page?
Upload to YouTube: set visibility to "Unlisted" (not Private). Copy the embed code (Share → Embed) and paste the <iframe> into your proposal/index.html. OR upload to Google Drive, right-click → Share → Anyone with link → Copy link, then use the link in an <iframe src="...">. Never commit the raw .mp4 to GitHub — video files are large and slow down git.
What happens at the Week 14 final presentation?
Each team gets 10 minutes: ~5 min live demo + ~3 min slides + ~2 min Q&A. You also submit a 2-minute screen-recorded video demo before the class. The site must be deployed on GitHub Pages and accessible via a public URL.
