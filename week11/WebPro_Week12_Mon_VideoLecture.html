🧠 What is State?

Props are data passed in to a component. State is data that the component manages itself — data that can change over time.

Props
  • Passed from parent
  • Read-only in child
  • Like function parameters
  • Cannot change inside child
State
  • Owned by the component
  • Can change over time
  • Like local variables — but special
  • Triggers a re-render when changed
When state changes → React re-renders the component → the UI updates automatically.

🪝 Introducing useState

useState is a React Hook — a special function that lets functional components remember data between renders.

import { useState } from 'react';

function Counter() {
  // Declare a state variable "count" with initial value 0
  const [count, setCount] = useState(0);
  //    ↑ current value  ↑ setter function  ↑ initial value

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}
useState returns an array: [currentValue, setterFunction]. We use array destructuring to name them.

🔄 State Updates Are Asynchronous

React batches state updates for performance. Never read state right after calling the setter — it might not be updated yet.

// WRONG — count might not be updated immediately
function handleClick() {
  setCount(count + 1);
  console.log(count); // still the old value!
}

// CORRECT — use the updater function when new state depends on old
function handleClick() {
  setCount(prev => prev + 1); // prev is guaranteed to be latest
  setCount(prev => prev + 1); // two increments work correctly
}
Updater function pattern

When new state depends on old state, always use the prev => newValue form. This is especially important inside setTimeout, event handlers, or when calling setState multiple times.

🎛️ Multiple State Variables

Call useState multiple times — once for each piece of independent state.

function UserProfile() {
  const [name, setName]           = useState('');
  const [age, setAge]             = useState(20);
  const [isEditing, setIsEditing] = useState(false);

  return (
    <div>
      {isEditing ? (
        <input
          value={name}
          onChange={e => setName(e.target.value)}
        />
      ) : (
        <h2>{name || '이름 없음'}</h2>
      )}
      <button onClick={() => setIsEditing(!isEditing)}>
        {isEditing ? '저장' : '편집'}
      </button>
    </div>
  );
}

🗃️ State with Objects

When state is an object, you must spread the existing state to preserve other fields — React does NOT deep-merge.

function RegistrationForm() {
  const [form, setForm] = useState({
    name: '',
    email: '',
    year: 1,
  });

  const handleChange = (field, value) => {
    setForm(prev => ({
      ...prev,         // keep all existing fields
      [field]: value,  // update only the changed one
    }));
  };

  return (
    <form>
      <input value={form.name}
             onChange={e => handleChange('name', e.target.value)} />
      <input value={form.email}
             onChange={e => handleChange('email', e.target.value)} />
    </form>
  );
}

📋 State with Arrays

Arrays in state must be treated as immutable. Never mutate directly — always create a new array.

function TodoList() {
  const [todos, setTodos] = useState([
    { id: 1, text: 'Read React docs', done: false },
  ]);
  const [input, setInput] = useState('');

  const addTodo = () => {
    setTodos(prev => [
      ...prev,                              // spread existing
      { id: Date.now(), text: input, done: false }, // add new
    ]);
    setInput('');
  };

  const toggle = (id) => {
    setTodos(prev => prev.map(t =>
      t.id === id ? { ...t, done: !t.done } : t
    ));
  };

  const remove = (id) => {
    setTodos(prev => prev.filter(t => t.id !== id));
  };
}

⬆️ Lifting State Up

When two sibling components need to share state, lift it up to their common parent and pass it down as props.

// Parent manages shared state
function App() {
  const [score, setScore] = useState(0);
  return (
    <div>
      <ScoreDisplay score={score} />
      <ScoreControls onIncrement={() => setScore(s => s + 1)}
                       onReset={() => setScore(0)} />
    </div>
  );
}

// Child just displays — receives score as prop
function ScoreDisplay({ score }) {
  return <h1>Score: {score}</h1>;
}

// Child triggers changes via callbacks
function ScoreControls({ onIncrement, onReset }) {
  return (
    <div>
      <button onClick={onIncrement}>+1</button>
      <button onClick={onReset}>Reset</button>
    </div>
  );
}

➡️ One-Way Data Flow

React enforces a unidirectional (one-way) data flow. Data flows down through props, events flow up through callbacks.

App (owns state)
↓ props (data down)
Child Component
↑ callbacks (events up)
App (updates state)
↓ re-renders with new props
Child Component (updates UI)
Never modify state from a child by directly accessing parent state. Always call a callback function passed as a prop.

🌡️ Real Example — Temperature Converter

function TemperatureConverter() {
  const [celsius, setCelsius] = useState('');
  const fahrenheit = celsius !== ''
    ? (parseFloat(celsius) * 9/5 + 32).toFixed(1)
    : '';

  return (
    <div className="converter">
      <h2>온도 변환기</h2>
      <label>
        섭씨 (°C)
        <input
          type="number"
          value={celsius}
          onChange={e => setCelsius(e.target.value)}
          placeholder="섭씨 입력..."
        />
      </label>
      {fahrenheit && (
        <p>= {fahrenheit} °F</p>
      )}
    </div>
  );
}

⚠️ Rules of Hooks

❌ Don't call Hooks conditionally
// WRONG
if (someCondition) {
  const [count, setCount] = useState(0); // Error!
}
❌ Don't call Hooks inside loops
// WRONG
items.forEach(item => {
  const [state, setState] = useState(item.value); // Error!
});
✅ Always call Hooks at the top level
function MyComponent() {
  const [a, setA] = useState(0);   // ✓ top level
  const [b, setB] = useState('');  // ✓ top level
  const [c, setC] = useState(false); // ✓ top level
  // ... rest of component
}

🧩 useState vs Regular Variables

❌ Regular variable — won't work
function Counter() {
  let count = 0; // resets every render!

  return (
    <button onClick={() => {
      count++;
      console.log(count); // increments...
      // but UI never updates!
    }}>
      {count}
    </button>
  );
}
✅ useState — works correctly
function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(c => c + 1)}>
      {count}
    </button>
  );
  // Clicking re-renders, UI updates! ✓
}
React only knows to re-render when you call a state setter function. Mutating regular variables is invisible to React.

✅ Summary — Key Takeaways

1
State is local, mutable data owned by a component. When it changes, the component re-renders.
2
useState(initialValue) returns [value, setter]. Call the setter to update state.
3
Updater form: setCount(prev => prev + 1) is safer when new state depends on old state.
4
Objects/Arrays: always spread or map to create a new reference. Never mutate directly.
5
Lifting state up: when siblings need shared state, move it to their common parent.
6
Rules of Hooks: call at the top level only — no conditionals, no loops.
7
One-way flow: data down via props, events up via callback props.
