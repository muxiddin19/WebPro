React State — useState Hook

Props flow data into a component. State is data that the component owns and can change over time. When state changes, React automatically re-renders the component to reflect the new data.

1. What is State?

State is dynamic data owned by a component — data that can change in response to user actions, timers, or network responses. Unlike props (which the parent controls), a component controls its own state.

Props

  • Passed from parent
  • Read-only inside child
  • Controlled by parent
  • Like function parameters

State

  • Owned by the component
  • Can change over time
  • Component updates itself
  • Like local variables — but persistent
💡

When React state changes, the component re-renders — React calls your function again with the new state value and updates the DOM efficiently.

2. useState Syntax

import { useState } from 'react';

function Counter() {
  // useState returns [currentValue, setterFunction]
  // The argument to useState() is the INITIAL value
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={() => setCount(count - 1)}>-1</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}
⚠️

Never call useState inside loops, conditions, or nested functions. Hooks must be called at the top level of your component, in the same order every render. This is "the Rules of Hooks".

Initial state types

const [count,  setCount]  = useState(0);           // number
const [name,   setName]   = useState('');           // string
const [isOpen, setIsOpen] = useState(false);        // boolean
const [items,  setItems]  = useState([]);           // array
const [user,   setUser]   = useState(null);         // null
const [form,   setForm]   = useState({ name: '', email: '' }); // object

Lazy initial state (for expensive computation)

// If initial value is expensive to compute, pass a FUNCTION
// (the function runs only once on mount, not every render)
const [data, setData] = useState(() => expensiveComputation());

3. Updating State — Rules

Rule 1: Never mutate state directly

// ❌ WRONG — mutating state directly does NOT trigger re-render
count++;
state.name = 'Amir';
items.push('new item');

// ✅ CORRECT — always call the setter function
setCount(count + 1);
setName('Amir');
setItems([...items, 'new item']); // create a NEW array

Rule 2: Updating objects — spread to copy first

const [user, setUser] = useState({ name: 'Amir', age: 20, city: 'Tashkent' });

// ❌ WRONG — mutates the object
user.age = 21;
setUser(user); // React sees the same object reference — no re-render!

// ✅ CORRECT — spread to create a NEW object, override what changed
setUser({ ...user, age: 21 });
// Result: { name: 'Amir', age: 21, city: 'Tashkent' }

Rule 3: Updating arrays — use non-mutating methods

const [items, setItems] = useState(['HTML', 'CSS']);

// Add item
setItems([...items, 'JavaScript']); // spread + append
setItems(prev => [...prev, 'React']); // functional update — preferred

// Remove item
setItems(items.filter(item => item !== 'CSS'));

// Update item
setItems(items.map(item => item === 'HTML' ? 'HTML5' : item));

Functional updates (when new state depends on previous)

// If new state depends on old, use the callback form of the setter
// This guarantees you get the LATEST state, not a stale closure
setCount(prevCount => prevCount + 1); // ✅ safe
setCount(count + 1);                   // ⚠️ can be stale in async contexts

4. Multiple State Variables

You can call useState as many times as you need. Each call tracks a separate piece of state.

function RegistrationForm() {
  const [name,     setName]     = useState('');
  const [email,    setEmail]    = useState('');
  const [isSubmit, setIsSubmit] = useState(false);
  const [errors,   setErrors]   = useState({});

  function handleSubmit(e) {
    e.preventDefault();
    const newErrors = {};
    if (!name)  newErrors.name  = 'Name is required';
    if (!email) newErrors.email = 'Email is required';

    if (Object.keys(newErrors).length > 0) {
      setErrors(newErrors);
      return;
    }

    setIsSubmit(true);
    // submit logic…
  }

  if (isSubmit) return <p>Thank you, {name}!</p>;

  return (
    <form onSubmit={handleSubmit}>
      <input value={name}  onChange={e => setName(e.target.value)}  placeholder="Name" />
      {errors.name  && <p style={{color:'red'}}>{errors.name}</p>}
      <input value={email} onChange={e => setEmail(e.target.value)} placeholder="Email" />
      {errors.email && <p style={{color:'red'}}>{errors.email}</p>}
      <button type="submit">Register</button>
    </form>
  );
}

5. Lifting State Up

When two sibling components need to share state, lift the state up to their nearest common parent. The parent holds the state and passes it down via props, along with setter callbacks.

// Parent holds shared state
function TemperatureApp() {
  const [celsius, setCelsius] = useState(0);
  const fahrenheit = celsius * 9/5 + 32;

  return (
    <div>
      <h2>Temperature Converter</h2>
      <CelsiusInput value={celsius} onChange={setCelsius} />
      <p>In Fahrenheit: {fahrenheit.toFixed(1)}°F</p>
    </div>
  );
}

// Child receives value + callback via props
function CelsiusInput({ value, onChange }) {
  return (
    <label>
      Celsius:
      <input
        type="number"
        value={value}
        onChange={e => onChange(Number(e.target.value))}
      />
    </label>
  );
}
✅

One-way data flow: State flows down as props; events flow up as callbacks. This makes React apps predictable — you always know where data comes from.

Exercise 2 — Add & remove items from a list

Task: Build a component with a text input and "Add" button. Items typed in the input are added to an array stored in state. Each item has a "✕" button that removes it from the list.

function TaskList() { const [tasks, setTasks] = useState([]); const [input, setInput] = useState(''); function addTask() { if (!input.trim()) return; setTasks(prev => [...prev, { id: Date.now(), text: input.trim() }]); setInput(''); } function removeTask(id) { setTasks(prev => prev.filter(t => t.id !== id)); } return ( <div> <input value={input} onChange={e => setInput(e.target.value)} placeholder="New task" /> <button onClick={addTask}>Add</button> <ul> {tasks.map(task => ( <li key={task.id}> {task.text} <button onClick={() => removeTask(task.id)}>✕</button> </li> ))} </ul> </div> ); }

function PlayerScore({ name, score, onIncrement, onDecrement }) { return ( <div> <h3>{name}: {score}</h3> <button onClick={onDecrement}>−</button> <button onClick={onIncrement}>+</button> </div> ); } function ScoreBoard() { const [p1, setP1] = useState(0); const [p2, setP2] = useState(0); return ( <div> <PlayerScore name="Player 1" score={p1} onIncrement={() => setP1(p => p + 1)} onDecrement={() => setP1(p => p - 1)} /> <PlayerScore name="Player 2" score={p2} onIncrement={() => setP2(p => p + 1)} onDecrement={() => setP2(p => p - 1)} /> <h2>Total: {p1 + p2}</h2> </div> ); }

🪝 useState — Cheat Sheet

Basic syntax

const [val, setVal] = useState(init);

Update primitive

setCount(count + 1);
// or functional:
setCount(prev => prev + 1);

Update object

setUser({ ...user, age: 21 });
// spread first, then override

Add to array

setItems(prev => [...prev, newItem]);

Remove from array

setItems(items.filter(x => x.id !== id));

Toggle boolean

setIsOpen(prev => !prev);

Rules of Hooks

✅ Top level only
✅ React functions only
❌ Not in loops/if
❌ Not in callbacks
