🌍 What are Side Effects?

A side effect is anything that affects something outside the current function's scope. In React components, side effects include:

  • Fetching data from an API (network request)
  • Setting up timers (setTimeout, setInterval)
  • Subscribing to events (resize, scroll, WebSocket)
  • Updating the document title (document.title)
  • Integrating with third-party DOM libraries
  • Storing data in localStorage
These can't go directly in render because render should be a pure function — same input → same output, no side effects.

⚡ Introducing useEffect

useEffect tells React: "after rendering, run this function." It's the main way to perform side effects in functional components.

import { useState, useEffect } from 'react';

function PageTitle({ title }) {
  useEffect(() => {
    // This runs after every render where title changed
    document.title = title + ' | Web Programming';
  }, [title]); // ← dependency array

  return <h1>{title}</h1>;
}
Syntax
useEffect(effectFn, [deps]);
//           ↑ runs after render   ↑ optional array of dependencies

🔗 The Dependency Array

Dependency arrayWhen does the effect run?
OmittedAfter every render (dangerous — often causes infinite loops!)
[] (empty)Once — only after the first render (component mount)
[a, b]After the first render, then whenever a or b changes
// Runs every render — usually wrong!
useEffect(() => { fetch(...); });

// Runs once on mount — good for one-time setup
useEffect(() => { fetch('/api/init'); }, []);

// Runs when userId changes — re-fetch profile data
useEffect(() => { fetch('/api/users/' + userId); }, [userId]);
Every value you use inside useEffect that comes from outside the effect must be listed in the dependency array.

🧹 Cleanup Functions

When your effect creates something that must be torn down (a timer, event listener, subscription), return a cleanup function.

function Clock() {
  const [time, setTime] = useState(new Date());

  useEffect(() => {
    // Set up a timer
    const timer = setInterval(() => {
      setTime(new Date());
    }, 1000);

    // Return cleanup function — called when component unmounts
    // or before the effect runs again
    return () => {
      clearInterval(timer); // ← clean up the timer!
    };
  }, []); // empty array = run once on mount

  return <p>현재 시간: {time.toLocaleTimeString('ko-KR')}</p>;
}
Without cleanup, the timer keeps running even after the component is removed — a memory leak!

🌐 Data Fetching Pattern

The most common use of useEffect — fetching data when a component mounts or when a dependency changes.

function UserProfile({ userId }) {
  const [user, setUser]       = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError]     = useState(null);

  useEffect(() => {
    setLoading(true);
    setError(null);

    fetch(`/api/users/${userId}`)
      .then(res => {
        if (!res.ok) throw new Error('User not found');
        return res.json();
      })
      .then(data => { setUser(data); setLoading(false); })
      .catch(err => { setError(err.message); setLoading(false); });
  }, [userId]); // re-fetch when userId changes

  if (loading) return <p>로딩 중...</p>;
  if (error)   return <p>오류: {error}</p>;
  return <h2>{user.name}</h2>;
}

🛑 Abort Controller — Preventing Stale Responses

When userId changes rapidly (user clicks fast), old fetch responses might arrive after newer ones — causing wrong data to display. Fix this with AbortController.

useEffect(() => {
  const controller = new AbortController();

  fetch(`/api/users/${userId}`, {
    signal: controller.signal  // link request to controller
  })
    .then(res => res.json())
    .then(data => setUser(data))
    .catch(err => {
      if (err.name === 'AbortError') return; // ignore cancel
      setError(err.message);
    });

  return () => {
    controller.abort(); // cancel in-flight request on cleanup
  };
}, [userId]);

📐 async/await in useEffect

useEffect's callback cannot be async directly (it would return a Promise, not a cleanup function). Create an inner async function instead.

// WRONG — useEffect async directly
useEffect(async () => {        // ❌ returns Promise, not cleanup
  const data = await fetchData();
}, []);

// CORRECT — inner async function
useEffect(() => {
  async function loadData() {
    try {
      setLoading(true);
      const res  = await fetch('/api/courses');
      const data = await res.json();
      setCourses(data);
    } catch (err) {
      setError(err.message);
    } finally {
      setLoading(false);
    }
  }

  loadData(); // call it
  // still returns cleanup normally:
  return () => { /* cancel if needed */ };
}, []);

📡 Event Listener Pattern

function WindowSize() {
  const [size, setSize] = useState({
    width: window.innerWidth,
    height: window.innerHeight,
  });

  useEffect(() => {
    const handleResize = () => {
      setSize({ width: window.innerWidth, height: window.innerHeight });
    };

    window.addEventListener('resize', handleResize);

    // Cleanup removes the listener when component unmounts
    return () => {
      window.removeEventListener('resize', handleResize);
    };
  }, []); // only on mount

  return (
    <p>창 크기: {size.width} × {size.height}</p>
  );
}
Always remove event listeners in cleanup — the same function reference must be passed to removeEventListener.

🔗 useState + useEffect Together

A common real-world pattern: fetch data when a search term changes (with debounce).

function BookSearch() {
  const [query, setQuery] = useState('');
  const [books, setBooks] = useState([]);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    if (!query.trim()) { setBooks([]); return; }

    const delay = setTimeout(async () => {
      setLoading(true);
      const res = await fetch(
        `https://openlibrary.org/search.json?q=${encodeURIComponent(query)}&limit=5`
      );
      const data = await res.json();
      setBooks(data.docs || []);
      setLoading(false);
    }, 400); // debounce: wait 400ms after typing stops

    return () => clearTimeout(delay); // cancel if query changes fast
  }, [query]);

  return (
    <div>
      <input value={query} onChange={e => setQuery(e.target.value)}
             placeholder="책 제목 검색..." />
      {loading && <p>검색 중...</p>}
      {books.map(b => <p key={b.key}>{b.title}</p>)}
    </div>
  );
}

⚠️ Common useEffect Mistakes

❌ Infinite loop — missing dependency array
useEffect(() => {
  setCount(count + 1); // changes state → re-render → runs again → ∞
}); // no deps = runs every render!
❌ Stale closure — missing dependency
useEffect(() => {
  document.title = `Score: ${score}`; // score is used but not listed!
}, []); // title never updates after first render
✅ Correct
useEffect(() => {
  document.title = `Score: ${score}`;
}, [score]); // listed — updates whenever score changes

🗺️ useEffect Lifecycle Analogy

If you've seen class components, here's how useEffect maps to lifecycle methods:

componentDidMount (run once after mount)
useEffect(() => { /* run once */ }, []);
componentDidUpdate (run when deps change)
useEffect(() => { /* run when count changes */ }, [count]);
componentWillUnmount (cleanup)
useEffect(() => {
  return () => { /* cleanup on unmount */ };
}, []);
In practice, the dependency-array mental model is cleaner than the lifecycle model.

✅ Summary — Key Takeaways

1
Side effects (fetch, timers, events) must go in useEffect, not directly in render.
2
useEffect(fn, [deps]) — runs after render, controlled by the dependency array.
3
Empty array []: runs once on mount. No array: runs every render (dangerous).
4
Cleanup function: return it from the effect to tear down timers, listeners, subscriptions.
5
Data fetching: use loading + error state, inner async function, AbortController for cleanup.
6
Stale closures: list every value used inside the effect in the dependency array.
